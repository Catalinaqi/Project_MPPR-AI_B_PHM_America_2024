## 3.3 Trasformazione dei Dati

### 3.3.1 Feature Engineering
**File di log:** `3.3.transformation.engineering_formulas_log.json`

**Formule applicate:**

| Nuova Feature | Equazione |
|:---|:---|
| `mgt_oat_ratio` | `mgt / (oat + 273.15)` |
| `specific_power_index` | `(np / ng) / (oat + 273.15)` |

- Conversione Kelvin (offset +273.15) per evitare divisioni per zero.
- Generazione di interazioni polinomiali di grado (configurabile).

**Conclusione:** Le feature ingegnerizzate migliorano il potere predittivo e introducono conoscenza termodinamica.

### 3.3.2 Scaling Robusto (RobustScaler)
**File di log:** `3.3.transformation.scaler_fit_trace.json`

- **Metodo**: `RobustScaler` (centratura per mediana, scala per IQR)
- **Parametri appresi** (esempi):
  - `mgt`: center = 592.7, scale = 57.1
  - `pa`: center = 366.4, scale = 776.4
  - `trq_margin`: center = 8.7, scale = 9.2

**Conclusione:** Lo scaling robusto ha allineato tutte le feature nello stesso spazio numerico (mediane ~0, IQR ~1), garantendo stabilità numerica per i modelli.

### 3.3.3 Serializzazione dell’Artefatto
**File artefatto:** `3.3.transformation.robust_scaler_regression.pkl`

- L’oggetto `RobustScaler` (con parametri `center_` e `scale_`) viene serializzato e riutilizzato per validazione e test, prevenendo data leakage.

**Conclusione:** Pratica corretta di model persistence e prevenzione della fuga di informazioni.

### 3.3.4 Analisi del Dataset Trasformato
**File sorgente:** `3.3.transformation.transformed_regression_train.parquet`

- **Boxplot post-scaling**: tutte le feature hanno mediana centrata a 0 e scale comparabili.
- **KDE sovrapposte**: feature con scale originariamente diverse (es. `pa`, `mgt`, `trq_margin`) ora mostrano distribuzioni che si sovrappongono attorno allo zero.
