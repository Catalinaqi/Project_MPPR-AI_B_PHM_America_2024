**Classificazione (`faulty`)**:

- **Fit teorici**: Il test di Kolmogorov-Smirnov ha mostrato che la distribuzione skew-normal si adatta meglio (`KS = 0.0772`) rispetto alla normale (`KS = 0.1378`) e alla gamma (`KS = 0.1314`).   - `ng`, `np`, `mgt`: CV molto basso (< 0.05), elevata stabilità. Deviazioni impercettibili in questi sensori a bassa varianza sono un chiaro indicatore di degrado meccanico.

Tutte le variabili sono state confrontate con i limiti operativi definiti nel file `ranges_quality_rules_config.yml` (es. `oat`: [-50, 60] °C, `ias`: [0, 250] kt, `pa`: [-1000, 20000] ft, ecc.).

### 3.2.3 Valutazione della Qualità dei Dati

#### 3.2.3.1 Collinearità

L'analisi della matrice di correlazione di Pearson non ha evidenziato coppie di variabili con correlazione superiore alla soglia di *data leakage* (±0.95) né alla soglia secondaria (±0.85). Questo *covariate shift* è coerente con dati di volo reali (profili di missione differenti tra le partizioni) e suggerisce l'adozione di modelli robusti alle variazioni distribuzionali (alberi, reti regolarizzate).

## 3.3 Fase 3 – Data Preparation

### 3.3.1 Selezione dei Dati (Step 3.1)

**Regressione** – Partendo da 10 colonne iniziali (ID + telemetria + `faulty` + `trq_margin`), sono state mantenute **9 colonne** predittive:
- Eliminate: `id` (chiave primaria, nessun potere predittivo), `faulty` (esclusa per evitare *data leakage* con il target `trq_margin`).

**Classificazione** – Stesse 10 colonne iniziali, mantenute **9 colonne** predittive:
- Eliminate: `id`, `trq_margin` (esclusa perché derivata deterministicamente dalle stesse dinamiche fisiche del target `faulty`, causerebbe *data leakage*).

In entrambi i casi, il filtraggio delle righe ha rimosso **0 duplicati** e **0 colonne costanti**, confermando l'integrità del dato dopo l'acquisizione.

### 3.3.2 Data Cleaning (Step 3.2)

**Regressione**:
- **Outlier Clipping (Winsorization)** sulla variabile target `trq_margin`:
  - Percentili: 1° e 99°.
  - Soglia inferiore: 27.73 | Soglia superiore: 92.80.
  - Record modificati: 68 nella coda sinistra, 70 nella coda destra (totale 138 record, 1.97%).
  - Operazione preserva il volume dei dati (nessun record perso), stabilizzando la Loss Function per i modelli di regressione.

**Classificazione**:
- **Nessun clipping** applicato: il target binario `faulty` non richiede normalizzazione o saturazione delle code.
- Verifica dei duplicati: **0 duplicati** rilevati, identità strutturale preservata.

### 3.3.3 Data Transformation (Step 3.3)

#### 3.3.3.1 Feature Engineering

Sono state create due nuove feature sintetiche, identiche per entrambi i task:

1. **`mgt_oat_ratio`** = `(mgt + 273.15) / (oat + 273.15)`
   - Rapporto termico gas/aria esterna. Indicatore di efficienza del motore.

2. **`specific_power_index`** = `(np + 0.001) / (ng + 0.001) / (oat + 273.15)`
   - Potenza normalizzata rispetto alla velocità del nucleo e alla densità dell'aria. Metrica sintetica di degrado meccanico.

Entrambe le formule includono la conversione in Kelvin (+273.15) per prevenire divisioni per zero e garantire coerenza fisica.

#### 3.3.3.2 Robust Scaling

Per entrambi i task è stato utilizzato un **RobustScaler** (centro = mediana, scala = IQR).

**Regressione**: Il modello ha appreso a scalare **congiuntamente** le features continue e la variabile target `trq_margin`. Questo garantisce che anche l'errore (Loss) venga calcolato in uno spazio numerico stabile.

**Classificazione**: Il modello ha scalato le features continue, mentre il target binario `faulty` è stato preservato nella codifica 0/1 (il RobustScaler ha assegnato parametri neutri: Center ≈ 0, Scale ≈ 1.0).

**Parametri chiave appresi (valori indicativi)**:
- `pa`: Center = 224.65, Scale = 500.65 (fattore di scala elevato, necessario per comprimere la magnitudo nativa).
- `mgt`: Center = 589.02, Scale = 57.89.
- `ng`, `np`: scale molto piccole (< 5), coerentemente con la loro bassa variabilità.

L'effetto dello scaling è stato validato visivamente per la feature `pa`: la distribuzione originale centrata a ~224 è stata traslata esattamente a 0, con le code compresse entro ±5 unità IQR.

## 3.4 Fase 4 – Data Modeling

### 3.4.1 Regressione (`trq_margin`)

- **Score function**: `LogScore` (Negative Log-Likelihood).
- **Base learner**: Alberi di decisione con `max_depth=2`, `min_samples_leaf=2`, `random_state=42`.
- **Numero di estimator**: `2` – questo valore volutamente basso indica che la run era in profilo `dev` (smoke test) per verificare l'integrità end-to-end del codice.

- **Strategia di split**: `GMM Stratified Cross-Validation` con **5 fold**.
- **GMM**: 4 cluster basati sulle feature `trq_measured`, `ng`, `np`, `ias`.

- **Best fold**: Fold 4 (NLL = 5.363, RMSE = 2.879).
- **Metriche aggregate**:  
  - NLL: media = 5.647, std = 0.206  
  - RMSE: media = 2.988, std = 0.108

#### 3.4.1.3 Feature Importance (XAI)

Le feature con maggiore impatto sul parametro `loc` (Media $\mu$) del target sono risultate:

L'NGBoost, restituendo una distribuzione probabilistica, cattura questa incertezza in modo esponenziale, fungendo da eccellente **Early Warning System**.

#### 3.5.2.2 Calibrazione degli Intervalli di Confidenza (Quantile Calibration)

L'analisi degli intervalli predittivi (file `5.2.evaluation.intervals_trace.json`) ha rivelato un **grave fenomeno di over-dispersion (underconfidence)**. Gli intervalli di confidenza predetti dal modello NGBoost sono eccessivamente ampi:

| Int_0.9 (10%)       | 10%               | 0%                 | 45°             | 55°             | -10%                   |

**Interpretazione**: Il modello genera distribuzioni Gaussiane con varianza ($\sigma$) troppo elevata. Anche l'intervallo mediano (50%) contiene il 100% dei dati reali, mentre l'intervallo più stretto (10%) non ne contiene nessuno. Questo rende il modello inutilizzabile per decisioni operative basate su soglie di confidenza, poiché i margini di sicurezza sono artificialmente larghi (safety margins inutilizzabili ingegneristicamente).

La diagnosi è **Underconfidence estrema**: il modello NGBoost (con soli 2 estimator) tende a produrre distribuzioni piatte, non riuscendo a discriminare adeguatamente la varianza locale. Si raccomanda un nuovo ciclo CRISP-DM focalizzato sull'iperparametro tuning (aumentare `n_estimators`, ridurre `learning_rate`) o su un diverso Base Learner.
